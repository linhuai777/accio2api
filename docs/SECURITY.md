# 安全模型

本文说明 accio2api 信任什么、不信任什么，以及已经实现了哪些防护。

---

## 密钥与凭证

| 项 | 存放 | 说明 |
|---|---|---|
| `API_KEY` | `.env` | 对外推理接口的密钥，客户端带 `Authorization: Bearer <它>` |
| `ADMIN_KEY` | `.env` 或 `data/.admin_key` | 管理端密钥。不设则首次启动自动生成 |
| `SECRET_KEY` | `.env` 或 `data/.secret_key` | **凭证加密主密钥**。丢失 = 已存账号全部不可恢复 |
| 账号凭证 | `data/credentials.enc` | AEAD 加密后落盘，权限 0600 |

**加密实现要点**：

- AEAD（带认证的加密）—— 密文被篡改会解密失败，而非静默返回垃圾
- **拒绝明文降级** —— 密钥缺失时启动失败，不会「先用明文顶着」
- 解密失败会 `log.error` 并在**健康巡检**中暴露，不会静默吞掉导致账号凭空消失

> 轮换 `SECRET_KEY` 时，旧凭证必须重新加密，否则全部失效。

## 网络信任边界

- **`X-Forwarded-For`** 仅在 `TRUSTED_PROXIES` 配置时才采信。未配置时一律用真实对端 IP，
  防止客户端伪造该头绕过限流。
- **服务端不提供 HTTPS**，请用反代终结 TLS。
- 管理端无内建账号体系 —— 密钥即身份。**暴露公网前必须额外加一层基础认证**（见 README）。

---

## 限流

三条**独立**计数线：

| 线 | 作用域 | 计数维度 |
|---|---|---|
| `inference` | `/v1/*` | API key |
| `admin` | `/admin/api/*` | 客户端 IP |
| `admin_login` | `/admin/api/login/start` | 客户端 IP（更严，会拉起真实浏览器） |

- 内存实现，进程重启清零 —— 自托管场景刻意不引入 Redis
- 计数操作加锁，并发安全
- `RATE_LIMIT_ENABLED=false` 一行关闭

## 已实现的防护

| 项 | 做法 |
|---|---|
| 登录会话端点 | `/login/{id}/frame`、`/login/{id}/input` 均**要求管理员鉴权**（否则可窥屏 / 操纵他人浏览器） |
| 别名归属 | 主地址兜底**默认关闭** —— 防止同收件箱下多账号互相认领验证码 |
| 错误响应 | 统一帧格式，**不泄露上游原始堆栈** |
| 流式缓冲 | 尾部窗口上限 8192 字节，防内存无限增长 |
| 依赖 | 尽量少（自己写限流而非引 slowapi），减少供应链面 |

## 调用审计

每次调用落盘：时间 / 模型 / 账号 / 用量 / 耗时 / 结果。管理端 Web UI 可查。

审计**不含**你的对话正文（除非显式开启正文捕获）。

## 系统提示词控制（可选）

用途：压制上游自带人设、拦截身份标识泄露。

```env
# ① 输入侧：在系统提示前追加一段前置语（软对抗，不保证上游完全听话）
PERSONA_PREFIX=                     # 留空 = 用内置默认；off = 关闭

# ② 输出侧：确定性拦截 —— 命中身份标识直接截断（硬兜底）
#            配置见 app/core/persona.py

# ③ 丢弃客户端发来的 system 消息（可选，防止客户端覆盖前置语）
PERSONA_DROP_CLIENT_SYSTEM=0
```

原理：输入侧是「建议」，输出侧是「执法」；两者配合才有稳定效果。

## 已知边界

- 上游风控（Baxia）可能随服务端更新调整，登录/注册链路需按现状复验
- 本项目**不绕过付费** —— 你账号的额度就是实际可用额度
- 无沙箱隔离，部署环境应按「运行不可信代码」对待
